WordPress

Plugins y mejoras

Página obligatoria para justificar qué se ha añadido a la instalación base de WordPress y por qué esas decisiones mejoran la web final frente a una configuración estándar.

Qué se ha mejorado

La web de REVON no se ha construido con la instalación básica de WordPress tal cual viene por defecto. Se ha trabajado sobre un tema propio y una estructura personalizada para conservar el diseño original del proyecto, reducir la dependencia de Gutenberg y convertir WordPress en un gestor de contenido útil, no en el lugar donde maquetar toda la web a mano.

  • Tema personalizado para mantener el estilo visual de la web original.
  • Separación entre páginas estáticas y blog nativo de WordPress.
  • Navegación por categorías y etiquetas en el blog.
  • Diseño responsive adaptado a móvil, tablet y escritorio.
  • Estructura pensada para usar Gutenberg solo cuando aporta valor real.

Plugins utilizados

Contact Form 7

Formulario

Se utiliza para gestionar el formulario de contacto dentro de WordPress sin tener que construir toda la lógica desde cero en el panel. Permite mantener el diseño personalizado de la página de contacto y, al mismo tiempo, resolver una necesidad real de la web.

Yoast SEO

Visibilidad

Se propone para optimizar títulos, descripciones y estructura básica de posicionamiento. Aunque el proyecto es académico, aporta una mejora clara sobre WordPress base al permitir una gestión más consciente de la indexación y la presentación de cada página y entrada.

LiteSpeed Cache

Rendimiento

Solo se recomienda si el hosting lo soporta bien. Su función sería mejorar el rendimiento y la velocidad de carga mediante caché y optimización, algo especialmente útil en una web con bastante peso visual e imágenes destacadas.

Por qué estas decisiones aportan valor

  • Evitan rehacer toda la web dentro del editor de bloques.
  • Permiten conservar una identidad visual coherente con la versión original.
  • Facilitan que el blog use categorías, etiquetas y navegación propia de WordPress.
  • Mejoran el mantenimiento del proyecto y separan bien diseño y contenido.
  • Demuestran un uso más consciente de WordPress como CMS y no solo como editor visual.
Base visual Tema propio

La mejora principal no es un plugin, sino la creación de una estructura personalizada que adapta el diseño original del proyecto al ecosistema WordPress.

Blog Categorías y etiquetas

Se aprovechan funcionalidades nativas de WordPress para cumplir con los requisitos del profesor y dar sentido editorial al contenido publicado.

Objetivo Menos Gutenberg

La web se plantea para que el editor de bloques se utilice lo mínimo posible, reservándolo solo para el contenido que realmente compensa editar desde el panel.
